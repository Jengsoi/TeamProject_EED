# 프로젝트 정의서

**SAFETY VISION — 산업안전 AI 보호구 착용 검사 시스템**

문서 버전: 3.0 / 개정일: 2026-09-10
개정 사유: 공식 과제 규격(3.2)에 따라 단일 WPF 프로세스 구조를 WPF 클라이언트 + C# 서버 + MySQL 구조로 전면 변경.

## 1. 목표와 고정 조건
- 개발 인원 3명, 개발 기간 7일.
- 웹캠 → **WPF 클라이언트** → **C# 서버(TCP/IP 소켓)** → **AI 추론(서버 내부)** / **MySQL** 구조.
- 클라이언트는 화면 표시·입력 검증·서버 요청만 담당한다. 판정과 DB 접근은 서버가 전담한다.
- 기본 웹캠 1대로 작업자를 자동 감지하고 안전모·안전조끼·마스크를 여러 프레임으로 검사하는 **실시간 지속 판정** 방식을 유지한다.
- 모델은 `ayushgupta7777/safetyvision-yolov8` v2를 유지한다. 별도 Person 모델은 추가하지 않는다.
- 실제 웹캠으로 검사 → 결과 → 저장 → 이력 확인까지 시연 가능한 완성을 우선한다.

## 2. 아키텍처 결정 사항 (3.2 요구사항 대응)
| 결정 항목 | 선택 | 근거 |
|---|---|---|
| AI 추론 위치 (3.2.3) | **1안**: C# 서버 내부에서 OnnxRuntime 직접 실행 | 모델이 이미 ONNX 형식이라 변환 불필요, 언어를 C# 하나로 통일해 3명·7일 규모에 맞는 복잡도 유지 |
| 영상 입력 방식 (3.2.5) | **1안**: 실시간 지속 판정 | 보호구 착용 검사는 계속 지켜봐야 하는 성격의 주제(졸음 감지형)이지 한 장만 보는 주제(알약 식별형)가 아님 |
| 모델 확보 방식 (3.2.6) | **2안**: 공개된 사전학습 모델 | 라벨링 데이터셋 구축 없이 7일 안에 검증 가능한 완성도 확보. 규칙 기반은 조명·각도 변화에 취약해 제외 |
| DB | MySQL 8.0 (Pomelo EF Core 프로바이더) | 과제 규격 지정, EF Core 연동 안정성 |

## 3. 구현 범위
필수 구현:
- 관리자 1계정 로그인·로그아웃 (서버에서 인증, 클라이언트는 자격정보만 전달).
- 관리자 대시보드, 현장 검사, 검사 결과, 검사 이력 (클라이언트 화면, 데이터는 서버 응답 기반).
- 웹캠 미리보기(클라이언트 로컬), 고정 ROI, Person 자동 감지·인원수 확인(서버 판정).
- 자동 검사, 프레임 누적, WORN/NOT_WORN/UNKNOWN 판정, 재검사 (서버 상태 머신).
- 결과 이미지와 검사 데이터 저장(서버→MySQL, 트랜잭션), 저장 실패 안내·저장 재시도.
- 실제 DB 기반 통계, 이력 페이지 이동·저장 결과 보기 (서버 조회 API).
- 여러 클라이언트 동시 접속, 연결 끊김·재연결 처리.

버튼만 구현: 통계 분석, 카메라 관리, 장비 관리, 사용자 관리, 시스템 설정.
클릭하면 `준비 중인 기능입니다.`를 표시한다 (클라이언트 로컬 처리, 서버 요청 없음).

## 4. 기본 흐름
```text
[클라이언트] 로그인 → 대시보드 → 현장 검사 화면 진입
   → 서버에 세션 시작 요청, 웹캠 프레임을 초당 최대 6회 서버로 전송
[서버] WAITING
   → ROI에 정확히 1명, 크기 조건 충족 → PERSON_DETECTED
   → 0.8초 유지 → INSPECTING
   → 목표 2초·12프레임 / 최대 5초 → RESULT → MySQL 저장(트랜잭션)
   → 재검사: 인원·크기 재확인 후 0.8초 대기 없이 INSPECTING
   → 저장 성공 후 ROI에 사람이 1초간 없음: WAITING
[클라이언트] 서버가 보낸 상태·안내 문구·결과를 그대로 표시
```
- 판정 상태 머신은 전적으로 서버 책임이다. 클라이언트는 서버 응답을 렌더링만 한다.
- 검사 시작·다음 작업자 버튼은 두지 않는다.
- 세부 상태 전이와 예외는 `02_요구사항.md`, 통신 규격은 `07_통신프로토콜.md`, 판정 규칙은 `05_AI모델명세.md`를 따른다.

## 5. 화면과 목업 적용
구현 화면: 로그인, 관리자 대시보드, 검사 이력, 현장 검사, 검사 결과.
`00_목업.png` 원본의 색상·카드·영상/상태 패널 배치를 유지한다. 명시적 변경 목록은 기존과 동일(장갑→마스크, CAM 01 고정 등)하며 `03_화면설계.md`에 정리한다.

## 6. 기술과 실행 환경
```text
C# / .NET 10 / C# 14 / Windows x64
WPF (클라이언트)
TCP/IP 소켓 서버 (C# 서버, 콘솔 또는 Worker Service)
CommunityToolkit.Mvvm (클라이언트)
OpenCvSharp4.Windows (클라이언트: 웹캠 캡처/전처리, 서버: 프레임 디코딩·letterbox)
Microsoft.ML.OnnxRuntime (서버, CPU)
Microsoft.EntityFrameworkCore + Pomelo.EntityFrameworkCore.MySql (서버)
LiveChartsCore.SkiaSharpView.WPF (클라이언트)
System.Text.Json (프로토콜 직렬화)
xUnit
```
- 클라이언트-서버는 TCP/IP 소켓, 길이 접두사 프레이밍으로 통신한다. 상세는 `07_통신프로토콜.md`.
- 서버는 다중 클라이언트 접속을 지원하며 클라이언트(TCP 연결)별로 독립된 상태 머신 인스턴스를 유지한다.
- MVVM은 클라이언트에 적용한다. 서버는 서비스/세션 계층으로 구성한다.
- 카메라·추론·DB 작업으로 UI 스레드(클라이언트)를 차단하지 않는다. 서버도 추론·DB 작업이 소켓 수신 루프를 막지 않게 비동기로 처리한다.
- 개발 준비 중 NuGet과 모델 다운로드는 필요하지만, 준비가 끝난 발표본은 오프라인 실행한다(로컬 MySQL 포함).
- 패키지의 실제 호환 버전은 Day 1에 복원·빌드·실행으로 검증하고 고정한다.

## 7. 솔루션과 실행 데이터
```text
SafetyVision.sln
src/
  SafetyVision.Client/      (WPF)
  SafetyVision.Server/      (TCP 서버, 콘솔 앱)
  SafetyVision.Core/        (상태 머신, 판정 로직, 도메인 모델 — App/Data 비의존)
  SafetyVision.Protocol/    (TCP 메시지 DTO, 프레이밍 유틸)
  SafetyVision.Data/        (EF Core MySQL, 계정·검사 저장, 이력·통계 조회)
tests/
  SafetyVision.Tests/
models/
  safetyvision_v2_640.onnx   (서버 실행 디렉터리 기준)
```
- Client: UI, 화면 전환, 웹캠 캡처, TCP 클라이언트 통신.
- Server: 세션 관리, TCP 리스너, ONNX 추론 어댑터, Core/Data 조립(DI).
- Core: 서비스 인터페이스, 상태 머신, ROI/PPE 연결, 순수 누적 판정 (UI/DB/네트워크 비의존).
- Protocol: Client·Server가 공유하는 메시지 계약(JSON DTO), TCP 프레이밍 헬퍼.
- Data: EF Core, 계정·검사 저장, 이력·통계 조회 (MySQL, Pomelo).
- 의존성: Client → Protocol, Server → Core/Data/Protocol, Data → Core. Core는 App/Data/네트워크 비의존.
- 모델은 서버 실행 디렉터리의 `models/safetyvision_v2_640.onnx`로 배포한다.
- MySQL은 서버와 같은 머신에 co-locate. 연결 문자열은 서버 설정 파일로 분리한다.
- 설정 파일은 서버 측 `appsettings.json`(또는 `settings.json`); 없으면 `05_AI모델명세.md`의 초기값으로 생성한다. 설정 UI는 제외한다.

## 8. 제외 범위
- 회원가입·비밀번호 변경·계정 관리·자동 로그인.
- 복잡한 RBAC·Refresh Token·별도 ASP.NET Core 서버·SignalR (직접 TCP/IP 소켓으로 구현).
- RTSP·다중 카메라·사용자/장비/카메라/설정 CRUD.
- 모델 업로드·버전 관리 UI·추가 모델·재학습.
- 얼굴 인식·신원 추적·모바일/클라우드/MSI.
- 연결 끊김 시 진행 중 검사의 서버 측 보류·복구(재연결 시 이어가기)는 구현하지 않는다. 끊기면 즉시 취소한다.

## 9. 완료 기준
- Windows 발표 PC에서 서버·클라이언트 각각 `dotnet build`와 실제 ONNX 정지 이미지 추론 성공.
- 클라이언트-서버 TCP 통신, 다중 클라이언트 동시 접속, 연결 끊김 시 안전한 취소 확인.
- 웹캠 자동 검사, 재검사, 저장(MySQL), 이력, 실제 DB 통계가 연결됨.
- 미검출을 미착용으로 확정하지 않고 미확인으로 처리함.
- 검사 취소·중복 저장·모델/카메라/저장/DB 연결 오류를 처리함.
- 판정 수치는 검증된 정확도 보장이 아닌 초기 설정값. Day 1 실측 후 조정값과 이유를 기록함.

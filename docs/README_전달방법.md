마스터 프롬프트의 "지금 먼저 할 일"대로 분석만 해. 아직 구현하지 마.
v3.0 문서에 확정한 기본값(클라이언트-서버 구조, TCP/IP 소켓, MySQL, 서버 내부 AI 추론)을 기준으로 판단하고,
문서에서 답을 찾을 수 있는 질문은 하지 마.

- 모델 없이 UI 개발은 명시적 Fake로 가능하지만 최종 완료 기준은 실제 모델 연결이다.

## 4. 고정된 실행 기본값
- **WPF 클라이언트 1개 + C# 서버(TCP/IP 소켓) 1개**, 기본 웹캠 인덱스 0, CAM 01, 서버 CPU 추론.
- 초기 관리자: admin / SafetyVision!2026. 최초 생성 때만 Seed, 비밀번호는 해시 저장(서버 측 MySQL).
- **DB: MySQL 8.0**(Pomelo EF Core 프로바이더), 연결 문자열은 서버 설정 파일에 분리.
- 이미지: 서버 머신의 `%LocalAppData%\SafetyVision\snapshots\yyyyMMdd\inspection_{id}.jpg`.
- 서버 설정: `appsettings.json`(또는 `settings.json`, 서버 실행 디렉터리 기준).
- 목표 2초·12프레임 / 최대 5초, 최소 5프레임, 최소 유효표와 70% 판정.
- 백분율은 판정 일치율, 미확인은 `—`. 미검출을 미착용으로 확정하지 않는다.
- 설정 UI는 없다. 파일 변경 후 재실행하며 조정값과 이유를 기록한다.
- **TCP 메시지는 길이 접두사(4바이트) + 타입(1바이트, JSON/이미지 구분) 프레이밍을 사용한다**(`07_통신프로토콜.md`).
- **다중 클라이언트 동시 접속을 지원하며, 연결이 끊기면 해당 세션의 진행 중 검사는 즉시 취소(저장 안 함)한다.**

## 5. 이번 개정(v3.0)에서 교체한 내용
- 단일 WPF 프로세스 구조를 **WPF 클라이언트 + C# 서버(TCP/IP) + MySQL** 구조로 전면 변경(과제 규격 3.2 대응).
- 상태 머신·ROI·PPE 연결·누적 판정 로직의 소유권을 서버로 명확화. 클라이언트는 표시·입력·요청만 담당.
- SQLite → MySQL(Pomelo), 연결 문자열 서버 설정 파일로 분리, 판정에 사용한 모델 이름·버전 컬럼 추가.
- TCP 통신 프로토콜 문서(07) 신규 작성: 프레이밍, JSON 규격, 메시지 카탈로그, 오류 처리, 동시성.
- 다중 클라이언트 동시 접속, 연결 끊김 시 즉시 취소(복구 없음) 정책 명시.
- 웹캠 프레임 전송(클라이언트→서버, JPEG, 초당 최대 6회)과 로컬 미리보기 분리 요구사항 추가.
- 3명 역할과 7일 일정을 서버/프로토콜 작업이 포함되도록 재배치.

## 6. 아직 실행으로 확인해야 하는 사항
이 문서는 구현 기준을 확정한 것이며 앱 실행 검증 보고서가 아니다.
실제 모델 파일 다운로드·로딩, NuGet 호환성, 발표 PC 추론 속도, 웹캠 검출 품질, **클라이언트-서버 간 프레임 전송 지연·처리량**, MySQL 연결 안정성, 저장 오류·오프라인 시연은 구현 과정에서 확인한다.
현재의 ROI/임계값/프레임/시간/TCP 전송 속도는 초기 설정값이며 실제 검증을 거쳐 조정할 수 있다.

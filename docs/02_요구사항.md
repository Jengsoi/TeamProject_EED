# 요구사항 명세서

문서 버전: 3.0 / 개정일: 2026-09-10
개정 사유: 클라이언트-서버 구조 반영. 판정·DB 접근은 서버 책임, 클라이언트는 표시·입력·요청만 담당.

## FR-00 통신 공통 (신규)
- 클라이언트-서버는 TCP/IP 소켓, 길이 접두사 프레이밍으로 통신한다. 상세 규격은 `07_통신프로토콜.md`.
- 각 TCP 연결이 하나의 세션이다. 서버는 연결별 독립된 상태 머신 인스턴스를 유지한다.
- 연결이 끊기면 서버는 해당 세션의 진행 중 검사를 즉시 취소(저장 없음)하고 세션 자원을 정리한다. 재연결 시 새 세션으로 WAITING부터 시작한다.
- 서버는 여러 클라이언트의 동시 접속을 지원한다. 한 세션의 오류가 다른 세션에 영향을 주지 않는다.
- 잘못된 형식의 요청·처리 중 예외는 클라이언트에 오류 응답을 반환하고 연결을 유지한다(치명적 오류가 아닌 한).

## FR-01 로그인·로그아웃
- 클라이언트 실행 시 로그인 화면. ID/비밀번호를 서버에 TCP 요청으로 전달한다.
- 서버가 최초 DB 생성 시 관리자 `admin` / `SafetyVision!2026`을 한 번 Seed한다.
- 서버는 사용자별 무작위 salt를 사용하는 PBKDF2 해시로 저장한다. 평문 비밀번호는 저장·전송 로그에 남기지 않는다.
- 실패 응답 메시지는 `아이디 또는 비밀번호를 확인해 주세요.`로 통일한다.
- 재실행 시 기존 계정·검사 기록을 초기화하지 않는다(MySQL 영속).
- 로그아웃 시 진행 중 검사 취소(서버), 클라이언트 카메라 해제, 로그인 화면 복귀.
- 회원가입·비밀번호 변경·자동 로그인은 제외한다.
- 클라이언트는 로그인 자격 증명 검증 로직을 갖지 않는다. 서버 응답만으로 화면을 전환한다.

## FR-02 관리자 메뉴·대시보드
메뉴 순서: 대시보드 / 현장 검사 / 검사 이력 / 통계 분석 / 카메라 관리 / 장비 관리 / 사용자 관리 / 시스템 설정.
앞의 3개만 실제 구현한다. 나머지는 클라이언트에서 `준비 중인 기능입니다.`를 표시한다(서버 요청 없음).
- 대시보드 진입 시 클라이언트가 서버에 통계 조회 요청을 보내고 응답으로 갱신한다.
- KPI: 전체 검사 / 정상 / 점검 필요. 전체 카드 아래 미확인 건수를 보조 표시한다.
- 장비별 착용률, 정상·점검 필요·미확인 결과 비율, 최근 검사 10건을 표시한다.
- 집계식·0건 처리·정렬은 `04_DB설계.md`를 따른다. 집계는 서버가 MySQL에서 계산해 응답한다.

## FR-03 웹캠·모델
- 현장 검사 화면 진입 시 클라이언트가 기본 웹캠 인덱스 0을 연다. 표시명 CAM 01.
- 클라이언트는 실시간 미리보기를 로컬에서 렌더링하고, 별도로 초당 최대 6프레임을 압축(JPEG)하여 서버로 전송한다. 미리보기와 전송은 분리되어 있어 네트워크 지연이 미리보기를 멈추지 않는다.
- 서버가 모델 파일과 입출력을 로딩 때 검증한다. 실패하면 서버는 해당 세션의 검사 기능을 비활성화하고 클라이언트에 오류를 통지한다.
- 모델·서버 연결이 없어도 클라이언트는 대시보드·저장 이력 조회는 가능하다(서버가 살아있고 DB 조회만 가능한 경우).
- 서버 연결 자체가 끊기면 클라이언트는 재연결을 시도하고, 실패 시 오류를 안내한다.
- Fake 판정은 서버 개발 설정에서 명시적으로 선택할 때만 사용하고, 서버가 클라이언트에 개발 모드임을 함께 통지해 화면에 표시한다. 실제 모델 실패 시 자동 Fake 전환 금지.

## FR-04 ROI·검사 시작
- ROI: 영상 가로 20~80%, 세로 5~95%. ROI 판정은 서버가 계산한다. 클라이언트는 서버가 알려준 ROI 좌표(비율)를 미리보기 위에 오버레이로만 그린다.
- Person 박스 중심이 ROI 안에 있으면 인원수에 포함한다. ROI 경계는 포함한다.
- ROI에 정확히 1명이며 박스 높이가 영상 높이의 40% 이상이어야 시작할 수 있다.
- 작으면 `카메라에 조금 더 가까이 서 주세요.`, 사람이 없으면 `검사 영역 안에 서 주세요.` — 서버가 문구를 결정해 응답하고 클라이언트는 그대로 표시한다.
- 조건이 0.8초 유지되면 시작한다. 서로 다른 분석 프레임에서 최소 2회 확인한다.
- 시작 전 미검출·다중 인원·크기 미달이면 안정 타이머를 초기화한다(서버 상태).
- ROI/PPE 좌표는 letterbox 좌표가 아닌 원본 영상 좌표를 사용한다(서버 내부 처리).

## FR-05 상태 머신 (서버 책임)
기본 상태: WAITING / PERSON_DETECTED / INSPECTING / RESULT.
오류 및 저장 상태는 별도 상태값으로 관리하고 기본 상태와 혼동하지 않는다.
서버는 세션(TCP 연결)마다 이 상태 머신 인스턴스를 독립적으로 소유한다.

| 현재 상태·사건 | 처리 |
|---|---|
| WAITING, 시작 조건 충족 | PERSON_DETECTED, 안정 타이머 시작 |
| PERSON_DETECTED, 0.8초 유지 | INSPECTING, 프레임·표·시간 초기화 |
| PERSON_DETECTED, 조건 불충족 | WAITING, 안정 타이머 초기화 |
| WAITING/PERSON_DETECTED, ROI 2명 이상 | 시작 금지, 한 명씩 안내 |
| INSPECTING, ROI 2명 이상 | 즉시 취소, WAITING, 누적값 초기화, 저장 안 함 |
| INSPECTING, ROI 0명으로 1초 미만 | 해당 프레임 제외, 현재 검사 유지 |
| INSPECTING, ROI 0명으로 1초 연속 | 취소, WAITING, 누적값 초기화, 저장 안 함 |
| INSPECTING, 1명이지만 크기 미달 | 해당 프레임 제외, 검사 시계는 계속 진행 |
| INSPECTING, 종료 조건 충족 | RESULT, 판정 고정, 최초 저장 1회(MySQL 트랜잭션) |
| RESULT, 사람 있음 | 결과 유지, 자동 재검사 금지 |
| RESULT, 저장 성공·ROI 0명 1초 연속 | WAITING |
| RESULT, 저장 성공·재검사 클릭 | 최신 인원·크기 확인 후 INSPECTING, 안정 대기만 생략 |
| RESULT, 저장 진행 또는 실패 | 결과 유지, 자동 복귀·재검사 잠금 |
| 검사 중 화면 이동·로그아웃 | 검사 취소·클라이언트 카메라 해제 요청 |
| 카메라·추론·DB 연결 오류 | 검사 취소·자동 검사 중단·오류 안내 |
| **TCP 연결 끊김(신규)** | 진행 중 검사 즉시 취소(저장 안 함), 세션 종료, 자원 정리 |

- 같은 처리 시점에서는 장치 오류/화면 종료 → 다중 인원/이탈 취소 → 정상 종료 순으로 우선한다.
- RESULT에서도 서버는 카메라 프레임 수신·Person 추론을 계속한다. 완료된 결과 데이터는 변경하지 않는다.
- 이탈은 실제 분석 결과가 ROI 0명인 상태의 연속 시간이다. 결과 미도착·추론 지연을 미검출로 계산하지 않는다.
- 새로운 인원 결과에서 1명 이상 확인되면 이탈 타이머를 초기화한다.
- RESULT에서 카메라·추론·DB 오류가 나면 확정 결과와 저장 기록은 유지하고 재검사·자동 복귀를 중단한다. 저장 작업은 계속 처리하며 대시보드 복귀는 저장 상태 규칙을 따른다.
- 재검사 클릭 시 새 프레임의 인원수·크기를 확인한다. 0명·2명 이상·크기 미달이면 시작하지 않는다.
- 신원 추적을 하지 않으므로 작업자 교대는 기존 작업자 이탈 → 대기 안내 → 다음 작업자 진입 순서로 진행한다.

## FR-06 분석 시간·누적 판정
- 최소 유지 2초, 목표 12프레임, 최대 5초. 분석은 초당 최대 6회, 동시에 1회만 실행한다.
- 종료: `(경과 시간 >= 2초 AND 분석 프레임 >= 12)` 또는 `경과 시간 >= 5초`.
- 최신의 서로 다른 프레임만 사용한다. 시작 전 안정 감지 프레임은 누적에 포함하지 않는다.
- 정확히 1명이 크기 조건을 충족한 프레임만 분석 프레임 N에 포함한다.
- 클라이언트가 서버에 전송하는 프레임 속도(초당 최대 6회)와 서버의 분석 속도 상한이 일치해야 한다. 클라이언트가 더 자주 보내도 서버는 상한을 넘겨 처리하지 않는다.
- 장비별 최소 프레임·유효표·70% 판정은 `05_AI모델명세.md`를 그대로 적용한다.
- 부족한 검출은 UNKNOWN. 보호구 미검출 자체를 NOT_WORN으로 바꾸지 않는다.
- 시간 종료로 N<5인 경우는 장비 3종 UNKNOWN으로 완료·저장한다. 인원/장치/연결 문제로 취소한 경우는 저장하지 않는다.

## FR-07 최종 결과·점수
- 3종 모두 WORN → NORMAL(정상).
- 하나 이상 NOT_WORN → CHECK_REQUIRED(점검 필요).
- 미착용 없이 UNKNOWN 존재 → UNCONFIRMED(미확인).
- 장비 상태 표시는 착용 / 미착용 / 미확인. 점검 필요는 검사 전체 결과명이다.
- Score는 선택된 상태의 표수 / 유효표수인 판정 일치율이다. 모델 confidence와 다르다.
- UNKNOWN이면 Score=NULL, 화면에는 `—`.
- 판정에 사용한 모델 이름·버전을 결과와 함께 저장한다(신규, `04_DB설계.md` 참고).

## FR-08 결과·재검사
- 대표 이미지, 해당 프레임의 실제 박스·클래스명, 장비 3종 누적 상태·판정 일치율, 최종 결과를 표시한다. 이미지는 서버가 인코딩해 클라이언트로 전송한다.
- `여러 프레임을 종합한 판정입니다.` 문구를 표시한다.
- 검사 시작·다음 작업자 버튼은 없고 재검사·대시보드 복귀를 제공한다.
- 재검사는 신규 검사 식별자(InspectionKey)와 기록을 사용한다. 기존 검사 기록은 유지한다.
- 저장 중 재검사·화면 이동을 잠근다. 저장 실패 시 재검사·자동 복귀는 잠그되 저장 재시도와 대시보드 복귀는 허용한다.
- 저장 실패 상태에서 복귀하면 `저장되지 않은 결과는 이력에 남지 않습니다.`를 안내하고 미저장 결과를 서버 메모리에서 폐기한다.

## FR-09 저장·저장 재시도 (서버 → MySQL)
- 완료 시 검사 1건 + 장비 정확히 3건 + JPG 1장을 저장한다. 판정과 업무 데이터(이력·집계)는 하나의 MySQL 트랜잭션으로 저장하고, 실패 시 전체 롤백한다.
- 검사 완료 시각, 최종 결과, 상태·표수·점수, 이미지 경로, 모델 이름·버전을 저장한다.
- DB 커밋과 이미지 파일 저장 모두 성공해야 성공으로 응답한다.
- 한쪽 실패 시 DB 롤백과 생성 파일 정리 후 결과를 서버 메모리에 유지한다.
- 오류 응답: `SAVE_FAILED` (클라이언트 표시 문구 `결과를 저장하지 못했습니다.`). 클라이언트는 `저장 재시도` 버튼을 제공한다.
- 저장 재시도는 같은 InspectionKey를 사용한다. 재검사는 새 InspectionKey를 사용한다.
- 저장 성공 여부가 불명확하면 같은 키로 이미 저장된 정상 기록을 먼저 조회한다. 중복 삽입하지 않는다.
- AI 추론은 이 트랜잭션 밖에서 수행한다(추론 완료 후 결과만 트랜잭션에 반영). 상세 스키마·파일 일관성 처리는 `04_DB설계.md`를 따른다.

## FR-10 검사 이력
- 최신순, 페이지당 50건. 이전/다음 페이지 제공, 범위 밖 이동 비활성화. 클라이언트는 페이지 번호를 서버에 요청하고 서버가 조건 검색·페이징을 수행한다.
- No / 검사 시각 / 안전모 / 안전조끼 / 마스크 / 최종 결과.
- 행 더블클릭 시 서버에 상세 조회를 요청해 저장된 결과 상세와 이미지를 연다. 이력 상세에서 재검사는 제공하지 않는다.
- 이미지가 없으면 기록은 유지하고 `이미지 파일을 찾을 수 없습니다.`를 표시한다.
- 조건 검색(기간, 결과 유형 등)은 서버 측 쿼리 파라미터로 전달한다.

## 비기능·검증
- UI 멈춤 금지(클라이언트), 서버 소켓 수신 루프 차단 금지, 추론 중첩 금지, 중복 검사·저장 금지.
- 서버는 세션별 CancellationToken과 검사 세대 식별자로 이전 검사의 늦게 도착한 결과를 무시한다.
- 여러 클라이언트가 동시에 접속해도 서버는 각 세션을 독립적으로 처리하며 한 세션의 부하가 다른 세션에 영향을 주지 않는다.
- 필수 의존성과 모델 준비 후 한 서버 PC에서 오프라인 실행(MySQL 포함).
- Windows에서 클라이언트·서버 각각 최종 `dotnet build` 성공, 핵심 판정/전이 테스트와 실제 웹캠 시연 수행.
- 수치 변경은 서버 설정 파일에서 수행하고 테스트 결과·이유를 실행 README에 기록한다. 설정 UI는 만들지 않는다.
- 예외 처리: 잘못된 입력(클라이언트 요청 검증), 연결 실패(TCP), 추론 실패(서버), 데이터베이스 오류(MySQL) 각각에 대해 명확한 오류 응답과 클라이언트 안내 문구를 정의한다.

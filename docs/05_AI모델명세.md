## 1. 고정 모델·준비
- 저장소: `ayushgupta7777/safetyvision-yolov8`, 모델 버전 v2.
- 원본 파일: `v2/best_640.onnx`.
- **서버(SafetyVision.Server)** 실행 디렉터리의 배치 경로: `models/safetyvision_v2_640.onnx`.
- **SafetyVision.Server** 프로세스 안에서 Microsoft.ML.OnnxRuntime CPU로 직접 실행한다(3.2.3 1안 확정). Python 서버나 별도 Person 모델은 사용하지 않는다.
- 원본 v1의 best.onnx 또는 v2의 best_896.onnx로 임의 교체하지 않는다.
- 모델 파일은 문서 ZIP에 포함되어 있지 않다. 개발 준비 시 아래 파일을 다운로드하고 서버 실행 출력에 복사하도록 설정한다.
- 실행 중 자동 다운로드는 하지 않는다. 파일 없음·metadata 불일치·로딩 실패 시 서버는 검사 기능을 비활성화하고 연결된 모든 클라이언트 세션에 오류를 통지한다.
- 판정 응답과 함께 저장되는 **모델 이름·버전**은 이 절의 저장소명·버전 문자열을 그대로 사용한다(`04_DB설계.md` Inspections.ModelName/ModelVersion).

출처: [모델 카드](https://huggingface.co/ayushgupta7777/safetyvision-yolov8)

다운로드: [v2/best_640.onnx](https://huggingface.co/ayushgupta7777/safetyvision-yolov8/resolve/main/v2/best_640.onnx)

배포 파일은 변경될 수 있으므로 Day 1에 사용 파일의 SHA-256과 다운로드 날짜를 실행 README에 기록한다. 모델을 바꾸지 말고 받은 파일을 검증한다.

## 2. 클래스
모델은 13개 클래스를 출력한다. 출력 전체를 해석한 뒤 다음 7개만 사용한다.

| 용도 | 클래스 이름 | 모델 카드상 예상 ID |
|---|---|---|
| 사람 | Person | 11 |
| 안전모 착용 | Hardhat | 3 |
| 안전모 미착용 | NO-Hardhat | 7 |
| 안전조끼 착용 | Safety Vest | 12 |
| 안전조끼 미착용 | NO-Safety Vest | 9 |
| 마스크 착용 | Mask | 4 |
| 마스크 미착용 | NO-Mask | 8 |

위 ID는 검증 참고값이다. 실제 파일 metadata의 이름→ID 매핑으로 결정한다. metadata가 없거나 이름이 다르면 추측하지 말고 모델 로딩 오류로 보고하여 Day 1에 확인한다.

## 3. ONNX 입출력·검출 처리
초기 연결 계약:
- 입력: float32 `[1,3,640,640]`, 모델 카드의 입력명 `images`. 실제 세션 metadata와 대조한다.
- 클라이언트가 TCP로 전송한 JPEG 프레임을 서버가 디코딩(OpenCvSharp)하여 BGR 영상을 얻고 RGB로 바꾼다.
- 원본 비율을 유지하여 640×640 안에 맞추고 남는 영역을 값 114로 중앙 패딩한다. 자동 stride 축소는 하지 않는다.
- float32로 변환, 255로 나누어 0~1, CHW 순서와 batch 차원 구성.
- 예상 출력: `[1,17,8400]`, 4개 좌표 채널 + 13개 클래스 점수. 별도 objectness 채널이 있다고 가정하지 않는다.
- 좌표는 중심 x/y·너비·높이로 해석한다. 13개 중 최고 점수 클래스를 후보로 택하고 confidence 0.40 미만을 제외한다.
- 필요한 7개 클래스를 남기고 클래스별 NMS IoU 0.45를 적용한다. 서로 다른 착용/미착용 클래스를 NMS로 서로 지우지 않는다.
- letterbox 비율·패딩을 역변환하여 원본(클라이언트가 캡처한) 영상 좌표로 되돌리고 영상 경계로 제한한다.
- 클라이언트 미리보기가 축소·여백 처리되더라도 ROI와 박스 계산은 서버가 받은 원본 프레임 좌표에서 수행한다. 초기 구현에서는 좌우 반전을 하지 않는다.
- 실제 tensor 이름·형식·출력이 예상과 다르면 자동으로 임의 해석하지 않는다. Day 1 정지 이미지로 연결 계약을 검증한다.

## 4. 카메라·ROI·인원
- 클라이언트가 기본 카메라 인덱스 0, 요청 해상도 1280×720으로 캡처한다. 미지원 시 장치가 제공하는 실제 해상도를 사용하고, 클라이언트는 실제 해상도를 서버에 함께 통지해 ROI가 비율로 계산되도록 한다.
- 클라이언트는 초당 최대 6프레임을 JPEG로 압축해 서버에 전송한다(`07_통신프로토콜.md`).
- 서버 ROI 계산: 가로 20~80%, 세로 5~95%, 경계 포함.
- confidence 기준을 통과한 Person 중 중심점이 ROI 안인 모든 사람을 센다. 작은 사람도 인원수에는 포함한다.
- 시작 조건: ROI 정확히 1명 + Person 높이 >= 영상 높이의 40% + 0.8초 유지. 최소 2개의 서로 다른 추론 결과가 필요하다.
- 시작 전 조건 불충족은 안정 타이머 초기화(서버 세션 상태).
- 검사 중 ROI 2명 이상은 즉시 취소, ROI 0명이 실제 관측상 1초 연속이면 취소한다.
- 0명이 1초 미만이거나 1명 크기 미달이면 해당 프레임은 N에 넣지 않는다. 검사 제한 시간은 계속 흐른다.
- 신원 추적을 하지 않는다. 빈 ROI를 거치지 않고 사람이 바뀌는 상황은 자동으로 구분하지 못하므로 발표는 한 명씩 진행한다.

## 5. 사람-PPE 연결
Person 원본 박스를 `(x0,y0,w,h)`라고 한다. PPE 박스 중심 `(cx,cy)`로 판단한다.

| 클래스 쌍 | 허용 중심 좌표 |
|---|---|
| Hardhat / NO-Hardhat | x0-0.05w ≤ cx ≤ x0+1.05w, y0-0.05h ≤ cy ≤ y0+0.35h |
| Mask / NO-Mask | x0-0.05w ≤ cx ≤ x0+1.05w, y0-0.05h ≤ cy ≤ y0+0.40h |
| Safety Vest / NO-Safety Vest | x0-0.05w ≤ cx ≤ x0+1.05w, y0+0.20h ≤ cy ≤ y0+0.75h |

- 위 경계는 원본 영상 범위 안으로 제한한다.
- 모든 검출 Person(ROI 밖 포함)에 대해 후보 연결을 확인한다.
- 하나의 PPE가 둘 이상의 Person에 위 조건으로 연결되면 모호한 PPE로 제외한다.
- 유일하게 검사 대상 Person과 연결되는 PPE만 누적에 사용한다.
- 최소 구현의 공간 규칙이며 머리 자세 추정·세분화·추가 추적 모델은 도입하지 않는다.
- 이 계산은 전적으로 서버(Core 계층의 순수 로직)에서 수행하며 네트워크·DB 의존이 없다.

## 6. 프레임별 표와 분석 프레임 N
- INSPECTING 시작 후 대상 Person이 정확히 1명이고 크기 조건을 만족한 서로 다른 프레임을 분석 프레임 N으로 센다.
- PPE가 미검출되거나 충돌하더라도 Person 조건이 맞으면 N에 포함한다.
- 장비별·프레임별 최대 1표. 중복 박스 수를 표수로 사용하지 않는다.

| 연결된 검출 | 누적 |
|---|---|
| 착용 클래스만 있음 | PositiveFrames(P) +1 |
| 미착용 클래스만 있음 | NegativeFrames(M) +1 |
| 둘 다 있음 | 충돌, P/M 증가 없음 |
| 둘 다 없음 | 정보 없음, P/M 증가 없음 |

## 7. 누적 판정과 점수 — 조건 순서 고정
장비별 유효표 E=P+M, 최소 유효표는 `max(3, ceil(N*0.50))`이다.
1. N<5이면 UNKNOWN.
2. E<max(3, ceil(N*0.50))이면 UNKNOWN.
3. P/E>=0.70이면 WORN, Score=P/E.
4. M/E>=0.70이면 NOT_WORN, Score=M/E.
5. 나머지는 UNKNOWN.

- UNKNOWN의 Score는 NULL, 표시 `—`. 유효표가 없을 때 나눗셈하지 않는다.
- Score는 판정 일치율 0~1. UI에서 100을 곱해 정수 백분율로 반올림한다.
- model confidence 또는 안전 확률로 표시하지 않는다. 박스에는 클래스명만 표시한다.

| N | P | M | 판정 | 이유 |
|---|---|---|---|---|
| 12 | 1 | 0 | UNKNOWN | 유효표 부족 |
| 12 | 7 | 2 | WORN, 약 78% | E=9, P/E>=0.70 |
| 12 | 2 | 7 | NOT_WORN, 약 78% | E=9, M/E>=0.70 |
| 12 | 4 | 4 | UNKNOWN | 한쪽 비율 70% 미만 |
| 12 | 3 | 0 | UNKNOWN | 최소 유효표 6 미달 |
| 5 | 3 | 0 | WORN, 100% | 최소 조건 충족; 전체 정확도 100%라는 뜻 아님 |
| 4 | 4 | 0 | UNKNOWN | 분석 프레임 5개 미만 |

## 8. 검사 시간·처리 루프
- 2초 이상 경과하면서 N>=12이면 종료한다. 그 전에 5초가 도달하면 즉시 종료한다.
- 최대 누적 N=12. 12개를 먼저 얻었다면 2초까지 인원 확인은 계속하되 표를 추가하지 않는다.
- 서버는 세션당 초당 최대 6회, 동시에 추론 1개. 클라이언트의 전송 속도도 동일 상한(초당 6프레임)을 지킨다. 시작 간격은 최소 1/6초이고 느린 추론은 완료 후 최신 프레임을 사용한다.
- 캡처(클라이언트)와 추론(서버)이 물리적으로 분리되어 있으므로, 서버는 수신 큐에 오래된 프레임을 쌓지 않고 항상 최신 프레임 우선으로 처리한다.
- 시간은 단조 증가 시계로 측정한다. 5초 종료 시 실행 중인 추론의 늦은 결과를 누적에 반영하지 않는다(세션의 검사 세대 식별자로 구분).
- N<5인 시간 종료는 3종 UNKNOWN으로 완료·저장한다. 사람 이탈/다중 인원/장치 오류/TCP 연결 끊김으로 인한 취소는 기록을 만들지 않는다.
- 안정 감지 0.8초의 프레임은 N에 포함하지 않는다.
- RESULT에서도 서버는 Person 감지 루프를 유지한다. 누적 결과는 고정, 저장 상태와 재검사 조건은 `02_요구사항.md`를 따른다.

## 9. 최종 결과·대표 이미지
- 모두 WORN → NORMAL.
- 하나 이상 NOT_WORN → CHECK_REQUIRED.
- 미착용 확정 없이 UNKNOWN 존재 → UNCONFIRMED.
- 대표 이미지는 한쪽 상태만 검출된 장비 종류가 가장 많은 프레임, 동률은 최신 프레임이다.
- 해당 프레임의 실제 박스를 이미지에 그린다. 누적 판정과 대표 이미지가 다를 수 있음을 화면 문구로 안내한다.
- 상세 저장 규칙과 N=0 이미지 대체는 `04_DB설계.md`를 따른다.

위치: **서버(SafetyVision.Server) 실행 디렉터리**의 `appsettings.json` 또는 `settings.json`(팀 선택). 클라이언트는 이 설정을 갖지 않는다. 없으면 아래 값으로 생성하고 서버 시작 때 읽는다. 설정 화면은 제외한다.

```json
  "PersonStableDurationSeconds": 0.8,
  "PersonLeaveDurationSeconds": 1.0,
  "MinAnalysisDurationSeconds": 2.0,
  "MaxAnalysisDurationSeconds": 5.0,
  "TargetAnalysisFrames": 12,
  "MinAnalysisFrames": 5,
  "MaxInferenceFps": 6,
  "MinEvidenceFrames": 3,
  "MinEvidenceRatio": 0.50,
  "DecisionRatio": 0.70,
  "PersonHorizontalMarginRatio": 0.05,
  "HeadTopMarginRatio": 0.05,

```
- ModelPath 상대 경로는 서버 실행 디렉터리 기준이다. DB(MySQL)·이미지 루트와 혼동하지 않는다.
- confidence/IoU/ROI 비율 범위, ROI 좌우·상하 순서, 시간 양수 및 최대>=최소, 목표 프레임>=최소를 검증한다.
- DecisionRatio는 0.5 초과~1 이하. 유효표 비율은 0 초과~1 이하.
- 잘못된 파일은 검사 비활성·설정 오류 안내로 처리하며 임의 값으로 덮어쓰지 않는다.
- MySQL 연결 문자열의 비밀번호는 실행 README에 원문으로 남기지 않는다(발표 환경 값만 별도 공유).

## 11. Day 1 검증·조정 범위
- 실제 ONNX metadata, 입출력 shape, class names, 이미지 좌표를 확인한다.
- 발표 서버 PC의 워밍업 후 추론 시간과 5초 동안 확보한 N을 측정한다. 클라이언트-서버 간 프레임 전송 지연도 함께 측정한다(신규).
- 실제 안전모·조끼·마스크의 착용/미착용 영상으로 정면·거리·조명을 확인한다.
- ROI·confidence·표수·비율·검사 시간은 검증된 성능 보장이 아닌 권장 초기값이다. 조정 시 코드 하드코딩 대신 서버 설정 파일과 README의 측정값을 함께 갱신한다.
- 모델은 유지한다. 속도가 부족하면 먼저 영상 조건, JPEG 압축 품질/해상도, 설정을 조정하고 결과를 보고한다.
- 최종 발표본에서는 UseFakeDetection=false이며 실제 모델 연결을 확인한다.

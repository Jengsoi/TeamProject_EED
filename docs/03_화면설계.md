# 화면 설계서

문서 버전: 3.0 / 개정일: 2026-09-10
개정 사유: 화면 구성·목업 적용은 기존과 동일하다. 차이는 모든 데이터·판정이 서버 응답으로 채워진다는 점뿐이다.

## 공통 디자인·목업 적용
- `00_목업.png`의 네이비/파랑, 흰 카드, 좌측 메뉴, 영상과 우측 상태 패널 배치를 유지한다.
- 목업 파일은 원본을 유지한다. 동작·표기 변경은 이 문서와 `02_요구사항.md`를 우선한다.
- 장갑은 이름뿐 아니라 아이콘·박스 클래스 표기도 마스크로 변경한다.
- 태블릿 목업은 WPF 클라이언트 내부의 현장 검사·결과 화면 디자인으로 사용한다. 별도 태블릿 앱은 없다.
- 카메라 표시는 CAM 01. 목업의 예시 날짜·건수·사진은 서버가 응답한 실제 데이터로 교체한다.
- 상태 공통 색상: 착용/정상 초록, 미착용/점검 필요 주황, 미확인 회색. 색상과 텍스트를 함께 사용한다.
- 모든 화면의 수치·문구·이미지는 클라이언트가 임의로 계산하지 않는다. 서버 응답 값을 그대로 표시한다.

## SCR-01 로그인
- SAFETY VISION 로고, 산업안전 AI 보호구 착용 검사 시스템 제목.
- ID 입력, PasswordBox, 로그인 버튼.
- 로그인 버튼 클릭 시 클라이언트는 TCP로 `LoginRequest`를 서버에 전송한다.
- 성공 응답 → 관리자 대시보드. 실패 응답 → `아이디 또는 비밀번호를 확인해 주세요.`.
- 서버 연결 자체가 실패하면 `서버에 연결할 수 없습니다. 연결을 확인해 주세요.`를 표시한다(신규).
- 초기 관리자 계정은 실행 README에 기재한다. 비밀번호를 일반 텍스트로 화면에 표시하지 않는다.

## SCR-02 관리자 대시보드
왼쪽 메뉴 순서:
1. 대시보드
2. 현장 검사
3. 검사 이력
4. 통계 분석
5. 카메라 관리
6. 장비 관리
7. 사용자 관리
8. 시스템 설정

1~3은 실제 화면, 4~8은 `준비 중인 기능입니다.` 메시지만 표시한다(서버 요청 없이 클라이언트에서 즉시 처리).
하단에 admin과 실제 로그아웃 버튼을 둔다(로그아웃은 서버에 세션 종료 통지 후 로그인 화면 복귀).

| 영역 | 내용 |
|---|---|
| 상단 카드 1 | 전체 검사 건수, 보조 문구 `미확인 N건` |
| 상단 카드 2 | 정상 건수 |
| 상단 카드 3 | 점검 필요 건수 |
| 장비별 현황 | 안전모·안전조끼·마스크 착용률 막대 |
| 검사 결과 비율 | 정상·점검 필요·미확인 3종 도넛 및 건수·백분율 |
| 최근 검사 | 최신 10건, No/시각/카메라/장비 3종/결과/이미지 |

- 카드 3개의 가로 배치를 유지한다. 정상+점검 필요+미확인=전체이다.
- 화면 진입 시 클라이언트가 서버에 `DashboardStatsRequest`를 보내고 응답으로 갱신한다.
- 최근 검사 카메라는 CAM 01. 장비 칸은 상태 텍스트를 사용한다.
- 기록 0건: 서버 응답에서 건수 0, 비율 `—`, 클라이언트는 차트 영역에 `검사 기록이 없습니다.`.

## SCR-03 검사 이력
표: No | 검사 시각 | 안전모 | 안전조끼 | 마스크 | 최종 결과.
- 최신순, 한 페이지 50건. 하단 이전/다음 버튼과 페이지 표시. 페이지 이동 시 클라이언트가 `HistoryPageRequest(page)`를 서버에 보낸다.
- 행 더블클릭 → 서버에 `InspectionDetailRequest(id)`를 보내 저장 결과 상세 모달(이미지·장비 상태·일치율·최종 결과)을 연다.
- 상세에는 닫기만 제공한다. 현장용 재검사 버튼이나 카메라 감지는 없다.
- 누락 이미지에는 `이미지 파일을 찾을 수 없습니다.` 표시(서버 응답에 이미지 없음 플래그 포함). DB 내용은 계속 표시한다.
- 시간은 서버가 저장한 UTC 시각을 클라이언트 PC 로컬 시간으로 변환해 `yyyy-MM-dd HH:mm:ss`로 표시한다.

## SCR-04 현장 검사
- 상단: 대시보드 복귀, SAFETY VISION, CAM 01, 현재 시각(클라이언트 로컬 시계).
- 왼쪽: 실시간 웹캠(클라이언트 로컬 렌더링)과 고정 ROI 오버레이(서버가 알려준 비율로 그림). 오른쪽: 현재 안내와 장비 3종 검사 상태(서버 응답).
- 검사 시작 버튼 없음. 현장 화면의 설정 아이콘 없음.
- 화면 진입 시 클라이언트는 서버에 세션 시작을 알리고 웹캠 프레임 전송을 시작한다. 화면을 벗어나면 전송을 중단하고 서버에 세션 종료를 알린다(카메라 해제).
- 장비를 분석 중일 때 확정 상태처럼 표시하지 않고 `분석 중`으로 표시한다.

| 상황 | 안내 |
|---|---|
| 대기 | 검사 영역 안에 서 주세요. |
| 작은 Person | 카메라에 조금 더 가까이 서 주세요. |
| 안정 감지 | 작업자를 감지했습니다. 잠시 서 있어 주세요. |
| 검사 | AI 분석 중... 잠시 서 있어 주세요. |
| ROI 다중 인원 | 한 명씩 검사해 주세요. |
| 모델 로딩 실패 | 모델을 불러올 수 없습니다. 모델 파일을 확인해 주세요. |
| 카메라 오류 | 카메라를 사용할 수 없습니다. 연결을 확인해 주세요. |
| 추론 오류 | AI 분석 중 오류가 발생했습니다. 화면에 다시 진입해 주세요. |
| 서버 연결 끊김(신규) | 서버 연결이 끊겼습니다. 재연결을 시도합니다. |

목표 2초·12프레임, 최대 5초이므로 고정된 2초 완료 약속이나 가짜 진행률을 표시하지 않는다. 모든 안내 문구는 서버가 상태 전이 시점에 결정해 클라이언트로 보낸다.

## SCR-05 현장 검사 결과
- 왼쪽: 저장 대상 대표 이미지(서버가 인코딩해 전송), 그 프레임의 실제 검출 박스와 클래스명.
- 오른쪽: 안전모·안전조끼·마스크의 누적 상태, 판정 일치율, 최종 결과.
- 장비 상태: `착용 78%`, `미착용 80%`, `미확인 —` 형태.
- 일치율 도움 문구: `판정 일치율은 유효한 검출 중 선택된 상태가 차지하는 비율입니다.`.
- 이미지 아래: `여러 프레임을 종합한 판정입니다.`.
- 박스에는 클래스명만 표시한다. 누적 일치율을 단일 프레임 confidence로 표시하지 않는다.
- 기본 버튼: 재검사 / 대시보드로 돌아가기. 다음 작업자 버튼 없음.
- 결과 화면 뒤에서도 서버는 Person 감지를 계속 수행한다. 고정 결과 이미지 자체는 갱신하지 않는다.

| 저장 상태 | 버튼·전환 |
|---|---|
| 저장 중 | `저장 중...`, 재검사·화면 이동 비활성, 자동 복귀 보류 |
| 저장 성공 | `저장 완료`, 재검사·복귀 허용, ROI 0명 1초이면 자동 대기 |
| 저장 실패 (`SAVE_FAILED`) | `결과를 저장하지 못했습니다.`, 저장 재시도·복귀 허용, 재검사·자동 복귀 비활성 |

- 저장 실패 후 복귀 시 `저장되지 않은 결과는 이력에 남지 않습니다.`를 알리고 서버 메모리의 미저장 결과를 폐기한다.
- 재검사는 새 프레임의 정확히 1명·크기 조건을 확인하고 0.8초 대기 없이 시작한다(서버가 판단, 클라이언트는 요청만 전송).
- 결과 상태에서 2명이면 기존 결과는 유지하고 한 명씩 안내하며 재검사는 허용하지 않는다.
- 저장 성공 전 이탈 시간이 충족되었더라도 성공 후 최신 인원 상태를 다시 확인하고 복귀한다.

## 화면 연결
로그인 → 대시보드 → 현장 검사 → 자동 검사 → 현장 결과.
현장 결과에서 재검사, 저장 후 사람 이탈에 따른 대기 복귀, 대시보드 복귀를 제공한다.
대시보드 → 검사 이력 → 저장 결과 상세는 별도 조회 흐름이다.
모든 흐름은 클라이언트-서버 TCP 요청/응답으로 이뤄지며, 상세 메시지 규격은 `07_통신프로토콜.md`를 따른다.

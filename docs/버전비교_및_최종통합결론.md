## 3. Codex SafetyVision 브랜치를 그대로 채택하지 않은 이유

`codex/safetyvision-inference-fixes`에는 Person 모델과 Mask 모델을 별도 파일로 지정하는 구조가 들어 있다. 그러나 브랜치에 `models/yolov8n.onnx`와 `models/mask_classifier.onnx`가 없고, 설정은 896 입력을 기본으로 하며 현재 확보된 검증 모델은 640 입력이다.

또한 외부 Person 모델이 없을 때 PPE 모델의 Person 검출만으로 대체하는 경로는 현재 PPE 모델의 Person 점수가 충분히 나오지 않아 검사 시작 조건을 만족하지 못한다. 최신 커밋의 anchor별 최고 클래스 선택 방식은 한 anchor에서 동시에 표현될 수 있는 헬멧/마스크 같은 다중 PPE 클래스를 잃을 가능성도 있어, 현재 검증된 안정화본의 다중 클래스 후처리를 유지했다.

따라서 해당 브랜치의 모델 입력 설정·세션 리소스 제한이라는 아이디어는 참고했지만, 누락된 모델 파일과 호환성 문제가 해결되기 전까지 최종 실행 경로에는 넣지 않았다.

## 4. 최종 통합 내용

- 사용자 현재본의 카메라·장비·사용자·시스템 설정 관리 화면과 DTO/서버 서비스를 포함했다.
- 관리 요청은 서버에서 관리자 계정을 재확인하며, 일반 로그인 세션에는 `FORBIDDEN`을 반환한다.
- 통계는 기간 필터, 장비별·일별·월별·카메라별 집계를 하나의 계약으로 통합했다.
- 저장한 카메라 인덱스와 해상도를 앱 시작 시 불러와 현장 검사 캡처에 반영하고, 화면 이탈 시 카메라 미리보기를 중지한다.
- 640 PPE 모델 경로 탐색, 다중 클래스 후처리, Person 대체 경로는 실제 확보된 모델에 맞춰 유지했다.
- 로그인 전 요청 차단, 세션별 프레임 순서·FPS 제한, 저장 재시도 중복 방지, DB 마이그레이션·카메라명 보완을 유지했다.

## 5. 검증 결과

최종 통합 폴더에서 수행한 확인 결과는 다음과 같다.

| 검증 | 결과 |
|---|---|
| `dotnet build SafetyVision.slnx --no-restore` | 오류 0개. NU1701 경고 6건(서로 다른 레거시 패키지는 3종) |
| MySQL 연결 xUnit 통합 테스트 | 48/48 통과 |
| 신규 `safetyvision_e2e` DB 마이그레이션·관리자 Seed | 통과 |

| TCP 인증·권한 | 비로그인 `UNAUTHORIZED`, 일반 로그인 관리 요청 `FORBIDDEN`, 관리자 로그인 성공 |
| 사용자 CRUD·장비·시스템 설정 조회 | 통과 |
| 기간 통계 조회 | 통과. 날짜 필터와 카메라별 집계 확인 |

검증용 DB의 테스트 데이터는 정리했다. 기존 `safetyvision_test`는 테이블은 있으나 마이그레이션 이력이 맞지 않는 상태였으므로, 새 환경에서는 빈 DB를 만들고 서버의 자동 마이그레이션을 적용해야 한다.

## 6. 남은 한계와 배포 주의점

- `OpenTK`·`SkiaSharp` 관련 NU1701 경고 6건(서로 다른 패키지 3종)이 남아 있다. 현재 빌드 오류는 아니지만, 장기적으로 net10 호환 패키지로 교체 검토가 필요하다.
- WPF 창을 실제로 띄워 웹캠을 선택하고 미리보기를 보는 GUI 검증은 이 환경에서 수행하지 못했다. 카메라 설정 저장/로드와 검사 반영은 코드 및 빌드 기준으로 확인했다.
- PPE 이미지 5장 검증은 경로 통과 확인이다. 정확도·재현율을 판단하려면 정상/미착용/가림/다인원/조명 변화가 포함된 별도 평가셋이 필요하다.
- TCP 자체에는 TLS가 없다. 다른 PC에서 사용할 때는 사설망 방화벽과 VPN 또는 TLS 계층을 함께 사용해야 한다.
- ONNX 모델은 `.gitignore` 정책상 소스 커밋에 포함되지 않는다. 최종 실행 폴더에는 `src/SafetyVision.Server/models/safetyvision_v2_640.onnx`를 배치하고 README의 SHA-256을 확인해야 한다.

## 7. 결론

현재 기준의 진짜 최종본은 사용자의 관리 기능 범위와 안정화본의 서버 안전성을 합친 `E:\프로그램\TeamProject_EED_true_final`이다. Codex SafetyVision 브랜치는 외부 모델 파일과 입력 크기 호환성이 확보되기 전까지 실사용 최종본으로 보기 어렵다. 최종 통합본은 별도 브랜치 `codex/true-final`에 커밋하며, 원래 두 작업 폴더는 수정하지 않는다.

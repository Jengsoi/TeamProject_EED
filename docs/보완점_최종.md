# SafetyVision 최종 보완점 및 검증 결과

작성일: 2026-09-14  
대상 커밋: `9a9244f` (보완점 기록 기준, `fix/final-hardening` 후속 수정 전)

## 결론

프로젝트는 WPF 클라이언트, C# TCP 서버, ONNX PPE 추론, MySQL 저장 구조를 갖추고 있다. 초기 검증에서 발견한 **인증 우회**, **검사 세션 정리**, **프레임 적체**, **DB-파일 보상 처리**, **이력 조건 검색** 문제는 `fix/final-hardening` 브랜치의 후속 수정에 반영했다. 솔루션 빌드와 DB 통합 테스트는 통과했으며, WPF 실제 카메라 캡처와 장애 주입·수정 후 raw TCP 전체 재시연은 이 환경의 Windows 애플리케이션 제어 정책으로 별도 확인이 제한된다.

## 이번 브랜치 수정 반영

| 보완점 | 반영 내용 |

| 검사 세션·대표 프레임 오염 | 로그인·로그아웃·화면 이탈·연결 종료·새 세션 시작 시 상태, 누적값, 대표 프레임, 저장 대기값, 세대 번호를 초기화한다. 저장 완료 재시도는 멱등 응답으로 처리한다. |

| 비밀정보·노출 범위 | 서버 설정 파일의 DB 비밀번호를 제거하고 환경 변수 주입을 필수화했다. 초기 관리자 시드도 `SAFETYVISION_ADMIN_INITIAL_PASSWORD`로 최초 배포 시 교체할 수 있게 했고, 기본 TCP 수신은 loopback으로 제한했다. 기존 커밋 이력에 남은 값은 별도 자격 증명 교체·이력 정리 대상이다. |

### MySQL 환경 및 전체 E2E 결과

관리자 권한 없이 실행할 수 있도록 MySQL Server 8.4.9 ZIP을 `E:\프로그램\mysql84`에 설치하고 데이터 디렉터리를 `E:\프로그램\mysql84-data`로 구성했다. `127.0.0.1:3306`에서 실행했으며, `safetyvision`과 별도 `safetyvision_test` DB를 만들고 프로젝트 계정으로 권한을 부여했다. Windows 서비스 등록은 하지 않았으므로 현재 검증 세션에서 실행 중인 로컬 프로세스 방식이다.

실제 C# 서버는 모델을 로드하고 두 개의 EF 마이그레이션 및 관리자 Seed를 완료했다. 실제 `ppe_01_contractor.jpg`를 raw TCP 프로토콜로 15프레임 전송해 `CHECK_REQUIRED` 결과를 만들었고, 저장 응답은 `SAVED`였다. 대표 이미지와 상세 조회 이미지가 각각 242,758바이트로 일치했으며, DB에서 검사 항목 3개·카메라명·모델명/버전·이미지 경로·마이그레이션 이력을 직접 확인했다. 조건 필터 이력 조회, 대시보드 합계 2건, 통계 합계 2건, 로그아웃도 정상 응답했다.

초기 경계 검증에서는 잘못된 로그인은 거절됐지만 로그인하지 않은 `DashboardStatsRequest`가 받아들여졌고, 저장 완료 후 새 세션의 첫 프레임이 `RESULT/SAVED`에 남는 문제가 재현됐다. 후속 수정으로 두 경로에 서버 인증 가드와 공통 세션 폐기 경로를 적용했다.

로컬 MySQL 8.4.9의 자체서명 TLS 인증서 때문에 기본 연결 문자열은 .NET 커넥터에서 SSL 인증 오류가 발생했다. 이번 검증의 임시 런타임 설정에는 `SslMode=None`을 사용했다. 실제 배포에서는 신뢰할 수 있는 인증서를 설치해 TLS를 유지하거나, 폐쇄된 로컬/사설망이라는 전제와 명시적 비TLS 설정을 문서화해야 한다.

## 우선순위별 보완점 (수정 전 진단)

아래 항목은 기준 커밋에서 확인한 원인과 완료 기준이다. 현재 반영 여부는 위의 `이번 브랜치 수정 반영` 표와 아래 최종 체크리스트를 기준으로 본다.

### P0 — 배포 전 반드시 조치

1. **TCP 인증 우회 차단**
   - 위치: `SafetyVision.Server/Networking/ClientSession.cs`, `TcpServerHost.cs`
   - 현재 로그인 성공 여부가 세션 상태로 저장·검증되지 않아, 클라이언트가 로그인 메시지 없이 검사·이력·통계 요청을 보낼 수 있다. 서버도 `IPAddress.Any`로 수신한다.
   - 조치: 세션별 `AuthenticatedUser`를 보관하고, 로그인·Ping 외 모든 메시지에 인증 가드를 둔다. 사용자 권한별 접근도 서버에서 재검증한다. 운영에서는 TLS 또는 사설망/VPN으로 TCP 구간을 보호한다.
   - 완료 기준: 로그인 없이 보낸 `InspectionSessionStart`, `HistoryPageRequest`, `StatisticsRequest`가 모두 거절되고 감사 로그에 남는다.

2. **비밀정보 제거 및 교체**
   - 위치: `SafetyVision.Server/appsettings.json`, `SafetyVision.Data/Seeding/AdminSeeder.cs`
   - DB 접속 정보와 초기 관리자 관련 민감 값이 소스/설정에 남아 있다.
   - 조치: 실제 비밀번호는 User Secrets·환경 변수·배포 비밀 저장소로 이동하고, 현재 노출된 DB 비밀번호는 교체한다. 초기 관리자 생성은 최초 배포용 일회성 절차로 분리한다.
   - 완료 기준: 저장소와 커밋 이력에 실제 비밀번호가 없고, 빈 환경에서는 비밀 설정 없이는 서버가 안전하게 기동을 거부한다.

### P1 — 기능 정확성과 안정성

3. **검사 화면 이탈·재입장 시 세션을 완전히 초기화**
   - 위치: `SiteInspectionViewModel.ReturnToDashboard`, `ClientSession.HandleSessionEndAsync`, `InspectionStateMachine`
   - 현재 화면에서 나가도 서버의 `_pendingSave`가 남고, `Result` 상태가 대기 상태로 돌아가지 않을 수 있다. 다시 입장하면 신규 검사 시작이 막힐 가능성이 있다.
   - 조치: 화면 이탈·연결 종료·로그아웃에 공통 `Discard/Reset` 경로를 두고, 대기 상태 전환·대기 저장 제거·분석 이미지 제거를 원자적으로 처리한다.
   - 완료 기준: 결과 화면에서 저장하지 않고 나간 뒤 재입장해도 새 검사 10회 연속 정상 시작·저장·취소가 가능하다.

4. **취소 이후 이전 사람의 대표 프레임이 재사용되지 않게 처리**
   - 위치: `ClientSession`의 `_analysisFrames`, 상태 취소 처리
   - 현재 성공 저장이나 세션 종료 시에는 프레임을 비우지만, 검사 도중 취소되는 경로에서는 잔존할 수 있다. 다음 검사 결과에 이전 사람 이미지가 연결될 수 있다.
   - 조치: 새 세션 시작, 모든 취소 원인, 실패, 연결 종료에 대해 분석 프레임·인덱스·누적 신뢰도를 함께 초기화한다. 세션 생성 번호를 붙여 프레임과 결과를 교차 검증한다.
   - 완료 기준: A 검사 취소 후 B 검사 저장 시 DB 이미지와 B의 결과가 항상 일치한다.

5. **프레임 적체(backpressure) 방지**
   - 위치: `SiteInspectionViewModel.CaptureLoop`, `ClientSession`, `SafetyVisionOptions.MaxInferenceFps`
   - 클라이언트가 약 6 FPS로 비동기 전송을 계속하고 서버는 추론을 동기 실행한다. 실제 추론/네트워크가 느려지면 오래된 프레임이 밀려 메모리 사용량과 결과 지연이 커질 수 있다. `MaxInferenceFps` 설정은 현재 실제 제한에 사용되지 않는다.
   - 조치: 클라이언트는 세션당 추론 요청을 1개만 진행하고, 새 프레임은 최신 1장만 유지한다. 서버는 세션별 FPS 제한·큐 길이 제한·오래된 프레임 폐기를 적용한다.
   - 완료 기준: 저사양 환경에서 10분 동작해도 큐가 무한 증가하지 않고, 화면 결과가 1초 이내의 최신 영상에 대응한다.

6. **DB 트랜잭션과 이미지 파일 저장의 불일치 보완**
   - 위치: `InspectionSaveService`
   - DB 트랜잭션 안에서 최종 이미지 파일을 이동한 뒤 커밋한다. 그 사이 DB 커밋이 실패하면 DB 행은 롤백되어도 최종 이미지 파일은 고아 파일로 남을 수 있다.
   - 조치: 임시 파일 생성 → DB 저장 → 커밋 후 최종 이동의 보상 처리 또는 outbox/재조정 작업을 둔다. 실패 시 생성된 최종 파일을 확실히 삭제하고, 고아 파일 탐지·정리 작업도 마련한다.
   - 완료 기준: DB 커밋 실패·디스크 오류·프로세스 강제 종료를 주입한 통합 테스트에서 DB 행과 파일이 불일치하지 않거나 재조정으로 복구된다.

7. **이력 조건 검색 UI 완성**
   - 위치: `HistoryViewModel`, `HistoryView.xaml`
   - 서버/조회 서비스에는 기간·판정 조건 필터가 있으나, 현재 화면은 항상 `null` 조건을 보내며 검색 입력 UI가 없다. 페이지 이동만 구현되어 있다.
   - 조치: 시작일·종료일·판정(PASS/FAIL/CHECK_REQUIRED) 필터, 검색 실행·초기화, 입력 검증(시작일 ≤ 종료일)을 추가한다.
   - 완료 기준: 조건 검색과 페이징을 함께 적용해도 총 건수·현재 페이지·표시 결과가 일관된다.

### P2 — 품질·성능·검증 범위

8. **통계 조회를 DB 집계로 전환**
   - 위치: `StatisticsQueryService`
   - 카메라별 통계가 데이터를 메모리로 모두 읽은 후 그룹화하는 방식이다. 데이터가 쌓이면 대시보드가 느려질 수 있다.
   - 조치: `GROUP BY`, 기간 조건, 적절한 인덱스(검사시각·카메라·결과)를 활용해 DB에서 집계하고, 대시보드에 필요한 쿼리를 묶는다.
   - 완료 기준: 목표 데이터량에서 대시보드 응답 시간과 메모리 사용량을 측정해 기준치를 만족한다.

9. **WPF 의존성 경고 해소**
   - OpenTK 3.3.1, OpenTK.GLWpfControl 3.3.0, SkiaSharp.Views.WPF가 `net10.0-windows`에서 호환성 경고를 낸다.
   - 조치: .NET 10 지원 버전으로 올리거나, 지원이 확인된 WPF 렌더링 대안을 검토한다. 업데이트 전 카메라 프리뷰·창 닫기·GPU/CPU 렌더링을 회귀 시험한다.
   - 완료 기준: 빌드 경고 제거 또는 유지 사유와 검증 결과가 문서화된다.

10. **테스트를 실제 운영 흐름까지 확장**
    - 현재 자동 테스트는 Core/Protocol/Data 중심이다. 이번에는 별도 raw TCP 검증기로 Server·ONNX·MySQL·이력 흐름을 수동 E2E 확인했지만, WPF 카메라·TCP 재연결·권한 경로는 자동 회귀 보장이 부족하다.
   - 조치: 격리 MySQL을 준비해 인증, 세션 취소, 저장 실패/롤백, 재연결 경쟁 상태, 이력 필터·페이징, 대표 이미지 일치를 자동화한다. 수동 시연은 정상 PPE뿐 아니라 미착용·부분 가림·다인원·어두운 환경도 포함한다.
    - 완료 기준: CI에서 DB 통합 테스트가 실제 실행되고, 필수 시나리오별 결과·스크린샷·로그가 남으며, 이번 raw TCP 시나리오가 자동 회귀 테스트로 편입된다.

11. **실제 PPE 판정 품질을 균형 있게 검증**
   - 이번 5장은 모두 헬멧과 안전조끼가 비교적 잘 보이는 정상 PPE 이미지여서, 양성 예시의 탐지 확인에 가깝다. 마스크는 5장 모두 검증하지 못했다. 다인원 이미지에서는 배경 헬멧도 검출됐다.
   - 조치: PPE 완비/헬멧 누락/조끼 누락/마스크 누락/부분 가림/다인원/원거리/역광 데이터를 라벨링해 정밀도·재현율·오검출을 측정한다. 현재 `UsePpeAsPersonProxy=true` 설정은 사람 검출을 PPE 검출로 대체하므로 다인원 장면에서 특히 검증이 필요하다.
   - 완료 기준: 항목별 기준치(예: PPE 누락 재현율, 정상 인원 오경보율)를 정하고 동일 테스트 세트에서 모델 버전별로 비교한다.

## 최종 시연 전 체크리스트

1. 격리된 MySQL 테스트 DB에서 자동 테스트 48개 통과를 확인했다. 실제 배포 PC에서도 `SAFETYVISION_TEST_MYSQL_CONNSTR`를 설정해 동일 결과를 확인한다.
2. 수정 전 raw TCP 기준 실제 모델 서버·DB·이력 흐름은 검증 완료했다. 수정 후 인증·세션 경계의 새 raw TCP 재시연은 Windows 애플리케이션 제어 정책(0x800711C7)으로 실행이 차단됐다.
3. 상태 머신의 결과 폐기·세대 무효화, 서버 인증 가드, 클라이언트 최신 프레임 전송 구조는 코드와 단위 테스트로 반영했다. 실제 웹캠과 네트워크 끊김은 발표 PC에서 재시연한다.
4. 저장 성공 시 결과·이미지·업무 데이터 일치는 확인했다. 저장 실패·강제 종료 사이의 장애 주입과 고아 파일 재조정은 운영 전 별도 시험이 필요하다.
5. raw TCP 조건 검색·상세·페이징 기반은 확인했고 WPF 조건 검색 UI를 반영했다. UI 표시와 실제 웹캠은 발표 PC에서 최종 확인한다.
6. WPF 패키지 호환성 경고 6건(OpenTK/SkiaSharp)은 남아 있으므로, 카메라 프리뷰 회귀 확인 후 지원 버전으로 올리는 작업을 별도로 진행한다.
